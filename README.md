# Чтобы собрать и запушить образы

```
cd backend && docker build -t delous/mes-backend . && docker push delous/mes-backend && cd ../frontend && docker build -t delous/mes-frontend . && docker push delous/mes-frontend
```

```
docker compose down && docker compose pull && docker compose up -d
```

docker run --name test-postgres -e POSTGRES_DB=postgres -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=devpassword -p 5432:5432 -d postgres:17

uvicorn app.main:app --reload

### Маршруты номенклатуры

Карточка номенклатуры содержит маршруты с упорядоченными шагами. У каждого
шага есть операция, рабочий пост и материалы. Первый шаг требует материалов;
последующие получают весь результат предыдущего шага и могут не иметь
дополнительных материалов. Количество материалов задаётся на указанный выпуск
маршрута и масштабируется при создании заказа.

Материал ссылается либо на номенклатуру, либо на результат другого маршрута
этой же карточки. Во втором случае весь маршрут ожидает завершения источника,
даже если результат нужен только позднему шагу. Циклические зависимости
запрещены. Общий маршрут создаётся один раз на строку заказа с суммарным
выпуском для всех потребителей. Маршруты, результаты которых не используются
другими маршрутами, формируют готовый выпуск; каждый такой маршрут выполняется
на количество из строки заказа. Дерево спецификации показывает номенклатуры
из материалов всех шагов, без узлов маршрутов и операций.

Перед запуском новой версии требуется `alembic upgrade head` из каталога
`backend`. Старые поля операции, рабочего поста и выпуска на номенклатуре,
а также таблица её материалов удаляются без переноса данных. Номенклатуры
сохраняются с пустым набором маршрутов; новые спецификации задаются в шагах.
Миграция удаления старого состава необратима.
Ранее созданные задачи заказов не пересчитываются.

Изолированные проверки графа и планирования: `python3 -m unittest discover -s backend/tests -v`.
